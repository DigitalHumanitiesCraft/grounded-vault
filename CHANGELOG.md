# Changelog

What changed in the template, for anyone running an instance built from it.

An entry is written when a change makes an existing instance do something or lets it do something new. Everything else stays in the git history, which is the complete record. Each entry names the date, what changed, and whether a running instance has to act. Versions are dates, because instances follow the template by commit rather than by release.

## 2026-09-26

**The distillate is defined as a knowledge document.** `knowledge/index.md`, `knowledge/schema.md`, `README.md` and `docs/concept.md` defined the distillate as the set of single statements extracted from a source, which reduced it to its list of core statements. It is now defined as the distilled knowledge document of one source, whose core statements carry the anchors while terms, open questions and appraisal stand beside them. `knowledge/index.md` now defines knowledge document as the genus in the Promptotyping sense, with two kinds: the distillate, bound to one source and under the content schema, and the project knowledge document, one of the six files in `knowledge/`, which rests on no source and stays exempt. This resolves a collision, since the schema had called only the six files knowledge documents and exempted them from the content schema. `docs/concept.md` called the assertion source-independent while the schema called it source-supported. The concept now uses source-supported as well, and `knowledge/schema.md` states what the term covers: the assertion rests on sources, it is not bound to any single one, and one source is enough. No rule, skeleton or check changed; running instances may carry the wording into their own `knowledge/index.md` and `knowledge/schema.md`.

## 2026-09-05

**Coverage faces the other way (act).** The source inventory gains a Coverage column, the blocks distillates anchor against the blocks a document representation carries, generated by `tools/inventory.py`. The validator raises `W-COVERAGE` where a distilled source falls below the share set with `--min-coverage`, half by default. Running instances add the column to the header row of the inventory in `knowledge/state.md` and regenerate it with `python tools/inventory.py . --write`. Every coverage warning is then a finding, answered by extending the distillate or by a journal entry on why the rest of the source is out of scope.

**Quotation checks name their text version (act).** A publication distillate carries `checked-against` beside `checked.quote`, naming the text version the quotation check ran on. The validator raises `W-VERSION` while it is missing. Running instances fill the field from their intake records; the value cannot be reconstructed from the vault, which is why it has to be written down.

**The quotation form is enforced.** The quotation block of a publication statement opens with the verbatim text in quotation marks and closes with the identifier in parentheses, read as one block over its lines. Before, a line with any quotation mark and any parenthesis passed.

**Computation scripts run only from `tools/analysis/`.** A data anchor naming a script elsewhere is refused as `E-COMPUTATION` before the validator would execute it.

**The no-op flag `--run-computations` is gone (act where used).** Computations have run by default since the flag became a no-op; an instance whose harness rules or workflows still pass it drops the flag. The continuous integration workflow now also lints `tools/` and `tests/` with ruff, whose configuration `pyproject.toml` already carried.

## 2026-08-10

**Self-report is a named case (act).** A source that speaks about itself, about its own priority, reach or achievement, covers the claim and never the matter the claim is about. `knowledge/schema.md` states the rule at the assertion type, `knowledge/operations.md` adds the verdict rule to the machine-review contract, and the `build-assertions` skill carries it as a step. Running instances should walk their assertions for statements taken from self-descriptive sources, since neither validation nor review flags this case on its own.

**Self-report widens to the displaced subject (act).** The entry above named one case of a wider defect, in which a passage supports the statement while its subject is not the matter the assertion is about. The second case is the state report, where a source shows the matter in one state at one time, such as a restored object, a dated inventory or a plan. `knowledge/schema.md` now states both at the assertion type, `knowledge/operations.md` gives both a verdict rule in the machine-review contract, and the `build-assertions` skill checks for both. Running instances should walk their assertions for statements taken from a dated state, since neither validation nor review flags this case on its own. An instance that pins a source by commit or by revision is the clearest occurrence, because there the state is recorded and the statement usually is not.

**Open questions hold questions and no findings (act).** A finding that could carry an assertion belongs in the core statements with its own anchor and ID. The section keeps minting no IDs, which is what makes it the one place where unanchored material may rest.

**The first production cycle runs vertically.** `SETUP.md` now says that the smallest full pass is finished before a second source is touched, and why the horizontal order produces nothing checkable until the last layer.

**Two explanatory passages.** `knowledge/schema.md` states the oracle the chain fastens onto, and it separates posit from assertion by kind rather than by ripeness. No rule changed.
